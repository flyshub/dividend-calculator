# 选股漏斗收成单一 deep module

Status: accepted

选股漏斗（四级判定、降级回退、输出整形）收进 `src/screening.py` 单一 deep module，中间对象类型化（FunnelConfig / FunnelCandidate / FunnelResult），删除按层拆分的薄 wrapper（screen_real_yield / screen_pr / screen_sustainability）与无生产调用方的 evaluate_stock_full；测试以漏斗 interface 为测试面（replace-don't-layer），数据获取留在编排层注入。

理由：真实 bug 藏在判定与降级的调用编排里（#81/#82），而旧测试只保护了离线纯函数；语义集中后判定、降级、测试同处一处，interface 变窄，未来修改一处生效。

Considered Options:
- A（采纳）：深 module = 纯判定流水线（判定 + 降级 + 输出整形），数据获取注入。深度集中在 bug 真正藏身处，测试面单一。
- B：深 module = 整条流水线（含数据获取/限流/刷新）。模块被迫同时碰网络与缓存，测试需大量注入，深度被稀释。
- C：只合并三个 screen_* 判定，降级与输出整形留在编排层。藏降级 bug 的编排层依旧不受测试保护。
